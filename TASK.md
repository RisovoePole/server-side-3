
Лабораторная работа №3
Разработка веб-приложения с использованием Express.js, EJS и middleware
Цель работы

Научиться разрабатывать структурированное веб-приложение на Express.js, использовать архитектуру MVC, создавать динамические страницы с помощью EJS, обрабатывать HTML-формы, применять middleware и выполнять операции добавления, просмотра, редактирования и удаления данных.

    Все требования, перечисленные в лабораторной работе, являются обязательными.

1. Создание проекта

Создайте папку:
 

lab3_name_surname

 

Откройте её в Visual Studio Code и выполните:
 

npm init -y
npm install express ejs

 

Создайте файл:
 

app.js

 
2. Тема приложения

Разработайте веб-приложение:
 

Система управления учебными курсами

 

Приложение должно позволять:

    просматривать список курсов;
    просматривать информацию об одном курсе;
    добавлять новые курсы;
    редактировать существующие курсы;
    удалять курсы;
    искать курсы;
    фильтровать курсы по семестру.

В этой лабораторной работе данные хранятся в массиве. После перезапуска сервера внесённые изменения могут быть потеряны. Подключение базы данных будет выполнено в следующей лабораторной работе.
3. Структура проекта

Организуйте проект следующим образом:
 

lab3_name_surname/
├── app.js
├── package.json
├── routes/
│   └── courseRoutes.js
├── controllers/
│   └── courseController.js
├── models/
│   └── courseModel.js
├── middleware/
│   ├── logger.js
│   └── validateCourse.js
├── views/
│   ├── courses/
│   │   ├── index.ejs
│   │   ├── details.ejs
│   │   ├── create.ejs
│   │   └── edit.ejs
│   ├── partials/
│   │   ├── header.ejs
│   │   └── footer.ejs
│   ├── 404.ejs
│   └── error.ejs
└── public/
    └── css/
        └── style.css

 

Назначение основных директорий:

    routes — определение маршрутов;
    controllers — обработка запросов;
    models — данные и операции с ними;
    middleware — промежуточная обработка запросов;
    views — EJS-шаблоны;
    public — CSS и другие статические файлы.

Запрещается размещать все маршруты и всю логику приложения непосредственно в app.js.
4. Исходные данные

В файле:
 

models/courseModel.js

 

создайте массив минимум из пяти курсов.

Каждый курс должен содержать:
 

{
    id: 1,
    title: 'Server-side Programming',
    teacher: 'Ivan Ivanov',
    credits: 5,
    semester: 1,
    description: 'Development of server-side applications using Node.js'
}

 

Обязательные свойства:
Свойство 	Назначение
id 	Уникальный идентификатор
title 	Название дисциплины
teacher 	Имя преподавателя
credits 	Количество кредитов
semester 	Номер семестра
description 	Описание дисциплины

Экспортируйте массив, чтобы его можно было использовать в Controller.
5. Настройка приложения

В app.js подключите Express:
 

const express = require('express');
const app = express();

 

Настройте EJS:
 

app.set('view engine', 'ejs');
app.set('views', './views');

 

Подключите обработку данных HTML-форм:
 

app.use(express.urlencoded({ extended: true }));

 

Подключите статические файлы:
 

app.use(express.static('public'));

 

Сервер должен работать на порту 3000.

После запуска приложение должно быть доступно по адресу:
 

http://localhost:3000

 
6. Маршруты приложения

Реализуйте следующие маршруты:
Метод 	URL 	Назначение
GET 	/ 	Перенаправление на список курсов
GET 	/courses 	Просмотр всех курсов
GET 	/courses/new 	Форма добавления курса
POST 	/courses 	Сохранение нового курса
GET 	/courses/:id 	Просмотр одного курса
GET 	/courses/:id/edit 	Форма редактирования
POST 	/courses/:id/edit 	Сохранение изменений
POST 	/courses/:id/delete 	Удаление курса

Маршруты должны находиться в:
 

routes/courseRoutes.js

 

Обработка маршрутов должна выполняться функциями из:
 

controllers/courseController.js

 
7. Главная страница и список курсов

При открытии:
 

http://localhost:3000/

 

пользователь должен быть перенаправлен на:
 

http://localhost:3000/courses

 

На странице /courses отобразите:

    заголовок приложения;
    кнопку добавления нового курса;
    форму поиска;
    фильтр по семестру;
    таблицу со всеми курсами.

Для каждого курса в таблице необходимо показать:

    название;
    преподавателя;
    количество кредитов;
    семестр;
    ссылку для просмотра;
    кнопку редактирования;
    кнопку удаления.

Если курсы отсутствуют, выведите сообщение:
 

Курсы не найдены

 
8. Просмотр одного курса

При переходе на:
 

GET /courses/:id

 

должна открываться отдельная страница с полной информацией о курсе:

    название;
    преподаватель;
    количество кредитов;
    семестр;
    описание.

На странице должны находиться:

    ссылка на список курсов;
    кнопка редактирования;
    кнопка удаления.

Если курс с указанным ID не существует, отобразите страницу ошибки с кодом:
 

404 Not Found

 
9. Добавление курса

На странице:
 

GET /courses/new

 

создайте HTML-форму.

Форма должна содержать:
 

Название дисциплины
Преподаватель
Количество кредитов
Семестр
Описание

 

Форма отправляет данные методом POST:
 

POST /courses

 

После успешного добавления курса пользователь должен быть перенаправлен на:
 

/courses

 

Новый курс должен появиться в списке.

ID нового курса должен создаваться автоматически. Пользователь не должен вводить его самостоятельно.
10. Редактирование курса

При открытии:
 

GET /courses/:id/edit

 

должна отображаться форма с текущими данными выбранного курса.

Пользователь может изменить:

    название;
    преподавателя;
    количество кредитов;
    семестр;
    описание.

Форма отправляет данные на:
 

POST /courses/:id/edit

 

После сохранения изменений пользователь должен быть перенаправлен на страницу обновлённого курса или на общий список.

Если курс не существует, верните страницу:
 

404 Not Found

 
11. Удаление курса

Для удаления используйте HTML-форму:
 

<form action="/courses/<%= course.id %>/delete" method="POST">
    <button type="submit">Удалить</button>
</form>

 

Перед отправкой формы пользователь должен подтвердить действие.

Например:
 

onsubmit="return confirm('Удалить этот курс?')"

 

После удаления пользователь должен быть перенаправлен на:
 

/courses

 

Если указанный курс не существует, отобразите страницу 404.
12. Поиск курсов

На странице списка добавьте форму поиска.

Пример запроса:
 

GET /courses?search=node

 

Поиск должен выполняться:

    по названию дисциплины;
    по имени преподавателя;
    без учёта регистра.

Например, запрос:
 

/courses?search=ivan

 

должен показать все курсы, преподавателем которых является Ivan.

Если параметр search отсутствует, необходимо показать все курсы.
13. Фильтрация по семестру

Добавьте фильтрацию:
 

GET /courses?semester=1

 

Пользователь должен выбирать семестр из списка.

Необходимо также поддержать одновременный поиск и фильтрацию:
 

GET /courses?search=node&semester=1

 

В этом случае курс должен соответствовать обоим условиям.
14. Валидация данных

Создайте middleware:
 

middleware/validateCourse.js

 

При добавлении и редактировании курса проверьте:

    название заполнено;
    преподаватель указан;
    количество кредитов является числом;
    количество кредитов больше нуля;
    семестр является целым числом;
    семестр находится в диапазоне от 1 до 8;
    описание заполнено.

Если данные некорректны:

    курс не должен добавляться или изменяться;
    пользователь должен увидеть понятное сообщение;
    ранее введённые данные не должны полностью исчезать из формы.

Примеры сообщений:
 

Название дисциплины обязательно
Количество кредитов должно быть положительным числом
Семестр должен находиться в диапазоне от 1 до 8

 
15. Middleware для логирования

Создайте файл:
 

middleware/logger.js

 

Middleware должен выводить в терминал информацию о каждом запросе:
 

HTTP Method | URL | Date and Time

 

Пример:
 

GET | /courses | 21.10.2026 14:25
POST | /courses | 21.10.2026 14:27

 

Middleware необходимо подключить до маршрутов, чтобы он применялся ко всему приложению.
16. EJS и Partials

Повторяющиеся элементы страниц необходимо вынести в:
 

views/partials/header.ejs
views/partials/footer.ejs

 

header.ejs должен содержать:

    название приложения;
    навигационное меню;
    ссылку на список курсов;
    ссылку на добавление курса.

footer.ejs должен содержать:

    имя и фамилию студента;
    группу;
    текущий год.

Partials необходимо подключить ко всем основным страницам.
17. Страницы ошибок

Создайте:
 

views/404.ejs
views/error.ejs

 
Страница 404

Должна отображаться, если:

    маршрут не существует;
    курс с указанным ID не найден.

Страница должна содержать:

    код 404;
    сообщение;
    запрошенный URL;
    ссылку на список курсов.

Страница общей ошибки

error.ejs должна использоваться при возникновении внутренней ошибки приложения.

Пользователю нельзя выводить технический stack trace.
18. Оформление приложения

Создайте:
 

public/css/style.css

 

Необходимо оформить:

    страницу;
    навигацию;
    таблицу;
    формы;
    текстовые поля;
    кнопки;
    сообщения об ошибках;
    страницу просмотра курса.

Кнопки просмотра, редактирования и удаления должны визуально отличаться.

Приложение должно оставаться читаемым при различном количестве курсов.
19. Требования к результату

В готовом приложении должны работать:

    просмотр списка курсов;
    просмотр одного курса;
    добавление курса;
    редактирование курса;
    удаление курса;
    поиск;
    фильтрация;
    одновременный поиск и фильтрация;
    валидация форм;
    логирование запросов;
    страницы ошибок;
    EJS-шаблоны и partials;
    CSS-оформление;
    архитектура MVC.
